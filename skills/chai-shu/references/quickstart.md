# 船板拆书 Quickstart（原版）

## 这套 skill 是做什么的

原版 `chai-shu` 面向普通 `拆书` 用户，负责调度：

1. 拆分扫描
2. 分章节概括
3. 全书概括
4. 人物概括
5. 事件概括

如果用户明确处于弱模型、弱工具调用、长程指令遵循较差的场景，不要继续用原版，直接改用 `chai-shu-weak`。

## 最常见的输入句式模板

### 自动化拆一本新书

```text
请帮我拆书。
任务：自动化拆书。
输入书籍：<源文件绝对路径>
```

### 只做拆分扫描

```text
请帮我拆书。
任务：拆分扫描。
输入书籍：<源文件绝对路径>
```

### 继续已有项目

```text
请继续这个拆书项目。
源项目目录：<Factory/拆书/{书名} 的绝对路径>
```

### 只做单项任务

```text
请帮我拆书。
源项目目录：<Factory/拆书/{书名} 的绝对路径>
任务：<分章节概括 / 全书概括 / 人物概括 / 事件概括>
```

## 路径怎么写才不歧义

1. 新书优先写"源文件绝对路径"
2. 已经开始的项目优先写"源项目目录绝对路径"
3. 只有在当前工作区里书名唯一时，才可以只写模糊书名
4. 用户只说"继续这本书"而不给路径时，先尝试匹配；若有多个候选，就要求更精确路径

## 标准执行顺序

```text
自动化拆书
  -> 拆分扫描
  -> 分章节概括
  -> 全书概括
  -> 人物概括
  -> 事件概括
```

如果用户只做单项任务：

- `分章节概括 / 全书概括 / 人物概括 / 事件概括` 都默认依赖前面的阶段
- 若前置阶段没完成，不要跳步，直接提示用户先补前置步骤

## 常见错误写法与推荐改写

### 错误：只写模糊书名

```text
拆书，帮我处理那个魔女文
```

推荐改写：

```text
请帮我拆书。
任务：自动化拆书。
输入书籍：{ROOT}/Factory/拆书/{书名}.txt
```

### 错误：想继续项目，但不给目录

```text
继续概括这本书
```

推荐改写：

```text
请继续这个拆书项目。
源项目目录：{ROOT}/Factory/拆书/{书名}
任务：分章节概括
```

### 错误：弱模型场景还在用原版入口

```text
请帮我拆书，我现在用的是弱模型
```

推荐改写：

```text
请使用"船板拆书（弱模型特调版）"处理这本书。
任务：自动化拆书。
输入书籍：<源文件绝对路径>
```

## 继续项目的状态报告示例

当用户选择「继续之前任务」时，AI 应输出如下格式的状态综合表格：

```text
📖 项目状态：《早知道不这么玩了！》

| 阶段 | 状态 | 说明 |
|------|------|------|
| 拆分 | ✅ | 39章已拆分 |
| 概括 | ✅ | 13组/13组全部完成 |
| 人物 | ✅ | 角色地位.yaml + 人物关系.yaml + 关系图谱.md |
| 事件 | 🔄 | 初次事件线追踪.md 已生成，事件线.yaml 未完成 |
| ABC  | ❌ | 未开始 |

推荐：从「事件概括」继续（阶段2：审视与确认）
```

**关键行为**：
- 表格中每一行都要有判断依据（文件是否存在、进度数据）
- 🔄 状态需说明当前停在哪一步
- 推荐项优先指向未完成的最早阶段
- 如果多个阶段都未开始，列出可选菜单让用户选择
